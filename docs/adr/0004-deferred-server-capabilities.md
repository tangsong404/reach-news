# 频道创建与重新生成等详情见 ADR

本文件记录在这轮重设计中「因为服务端能力尚未就绪而主动不做」的两项决定，避免后来者误以为是遗漏。

## 重新生成：等运行级端点

服务端现有 `POST /api/v1/briefs/:id/regenerate` 只能作用于已存在的日报，而 `missed` 的运行**不产出日报**（`publishBrief` 只在 `published` 时插入 brief）。因此对 `missed` 状态无法提供与 `failed`、`published` 一致的「重新生成」动作。

决定：等服务的运行级统一端点上线后再实现该动作；在此之前，界面上「重新生成」仅在存在日报时出现。不使用 `POST /runs/:id/retry` 冒充统一动作 —— 它返回的是新运行而非新日报，语义不同，混用会让用户以为原地重写了那一期。

## 频道创建：等连接器枚举接口

手机端可 `PATCH` 频道，但枚举连接器需要管理员 cookie 鉴权（`/admin/api/connectors`），`/api/v1` 下无对应端点。这意味着手机端创建的频道只能是 `connectorIds: []`，而启用状态下每次运行必然 `missed`（`no-material`）。

决定：等 `/api/v1/connectors` 开放后再上创建流程。在那之前，新建入口保留在视觉稿中，但实现在端点可用前不落地保存动作 —— 与其提供一个建出来就跑不起来的频道，不如暂时不给这个入口。

两处的共同原则：不把「服务端尚未支持」包装成客户端的一个按钮。
