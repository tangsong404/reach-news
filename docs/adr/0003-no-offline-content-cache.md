# 不做离线内容缓存，只持久化轮询基线

客户端不缓存日报与素材内容。断网时直接提示「当前无网络」，不展示任何历史内容；页面为空态而非降级内容。

唯一持久化的服务端相关状态是一个 `lastSeenAt` 时间戳（UTC ISO 8601），用作 `GET /api/v1/cursor?since=` 的基线，以便计算「哪些日报是新内容」。这是几十字节的元数据，不是内容缓存，两者在实现中应分开存放、分开命名，避免日后有人把内容缓存「顺手」加进同一个存储。

理由：分页是 `created_at DESC` 上的整数偏移，写入期间翻页不稳定，因此可靠的增量同步必须靠 ID 集合与重取，而不是靠缓存页；而在这个前提下维护内容缓存的失效逻辑，成本远高于它带来的收益。断网提示是诚实的，展示过期内容却不标注来源时间则不是。

**放弃的方案**：缓存最近 N 期（失效逻辑与偏移分页冲突，容易展示不完整或不一致的日报）；全量离线可读（存储与一致性成本最高，而服务端无删除与墓碑标记，缓存永远无法与远端对齐）。
